Week 10b — Evaluation as an Experiment

Pull today’s files

On Tuesday we evaluated the Husky Tech support agent by running each task once. Today we will run the evaluation as an experiment. We will compare two system prompts on the same 16 tasks, with five runs of every task under each prompt, and report the success rate with a 95% interval, pass^k, the paired difference between the prompts, the cost, and the failures.

W10b/
├── W10b.1_Evaluation_Experiments.ipynb  the experiment, step by step
├── W10a.1_Evaluating_Agents.ipynb       Tuesday's notebook, with the updated cohen_kappa
├── husky_env.py                         the orders, the policy, the tools, and a fixed date
├── eval_harness.py                      the agent, run_task, the checks, and the judge
├── eval_tasks.json                      the 16 tasks, each with its expected outcome
├── judge_calibration.json               18 replies with human labels, for checking the judge
├── results/gpt-4.1-mini/                our 160 saved runs, one .jsonl file per prompt
└── husky_support/                       the agent and its evaluation, packaged as scripts

Then open the notebook from your W10b copy, not from lecture-files, and select the .venv kernel. The notebook needs nothing new. To run the tests in husky_support, install pytest:

uv pip install pytest

W10b also contains a copy of the W10a notebook. Its cohen_kappa function now shows each chance term on its own line and returns nan when kappa is undefined, that is, when both raters give every item the same label. The notebook has a worked example of the function on ten labeled replies.

Running the experiment

The notebook runs 16 tasks, 5 times each, under 2 prompts: 160 agent runs. You don’t have to run them. Our results with gpt-4.1-mini are saved in results/gpt-4.1-mini/, and with RUN = False, which is the default, sections 3 to 7 analyze those files without calling a model.

To run the experiment with your own model, set RUN = True. Your results go to a folder named after your model.

  • With gpt-4.1-mini, it took us about six minutes.
  • On the Gemini free tier, set pause=4 in the run_experiment call to stay under 15 requests per minute. The experiment then takes over half an hour.
  • If it stops partway, through a 429 error or a closed laptop, run the cell again. Every run is saved as soon as it finishes, and the runs already in the file are skipped.

Section 8 sends a dataset and 32 agent runs to LangSmith, and runs only when USE_LANGSMITH = True. It needs LANGSMITH_API_KEY in your .env.

The packaged project

husky_support/ is the same agent and the same evaluation as scripts instead of a notebook: the application customers use in app/, and the evaluation suite that tests it in evals/. Its README.md explains the layout and the three rules behind it. Run these from inside the folder, in a terminal with the .venv activated:

cd W10b/husky_support

python score_eval.py results/gpt-4.1-mini      # score the saved runs; no model calls
python -m pytest tests                          # test the checks

python run_app.py                               # the chat app, at http://localhost:7860
python run_eval.py --model gpt-4.1-mini --condition policy --runs 1 --tasks t01,t16
python judge_eval.py --judge gpt-4.1-mini --validate

The scripts read the keys from the .env in your course project folder, so there is nothing to copy. The first two commands need no key at all. The app uses the model in the MODEL variable, gpt-4.1-mini unless you set another one.

For research projects, your FP3 needs the same parts: your own agent in app/, and your own tasks, checks, and metrics in evals/.
