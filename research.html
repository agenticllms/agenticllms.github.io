Final Project — Research Resources

Some pointers for research ideas in the graduate section.

This page is a starting point for finding your final project idea. The areas and papers below are initial directions; the strongest projects usually come from a question you find yourself while reading. What follows first is the one rule that is not optional.

The rule

An application domain alone is not a research contribution. “We will build a travel-planning agent” is not a project. “We investigate whether explicit constraint tracking improves long-horizon planning agents under changing constraints” is. The domain is the testbed; the mechanism is the contribution. Every strong project fits this template:

agentic mechanism → experimental manipulation → measured agent behavior

For example: memory policy → preference updates → stale-action rate. Or: tool descriptions → distractor similarity → tool-selection accuracy.

What fits in a semester

Feasible: controlled experiments on existing or synthetic benchmarks · fine-tuning small open-weight models (LoRA on a 4–9B model is a weekend on some GPU) · trajectory analyses over logged runs · architectural comparisons under a fixed token budget.

Not feasible: pretraining a model · large-scale RL training · months of human data collection

Where to look

  • NeurIPS proceedings — including the Datasets & Benchmarks track, where most agent benchmarks are published
  • ICLR on OpenReview — reviews are public; reading them teaches you how the field argues
  • ICML proceedings
  • ACL Anthology — ACL, EMNLP, NAACL; most tool-use and agent-NLP work lands here
  • COLM — the LLM-focused venue; young, high signal
  • Workshops are the goldmine for project-scale ideas. Each year NeurIPS, ICLR, and ICML host workshops on language agents, open-world agents, safe and trustworthy agents, and multi-agent systems. Workshop papers are shorter, newer, and closer to what a semester project can extend. Check the current workshop lists at neurips.cc, iclr.cc, and icml.cc, and search OpenReview for “agents” workshops.
  • For staying current: arXiv cs.CL and cs.AI, navigated with Semantic Scholar.

Starting directions

In what follows, we provide a few anchor papers per area. Read the anchors, then follow their citations forward on Semantic Scholar or Google Scholar to explore who cited this, and what they found wrong with it.

1. Benchmarking and evaluation

Task success alone poorly characterizes agents. Open questions: which trajectory features predict failure before a task ends, how many runs characterize reliability, how cost should enter benchmarks, and how reliable LLM-as-judge scoring really is.

  • τ²-bench — conversational tool-agents with a simulated user
  • SWE-bench — the coding-agent benchmark and its saturation story
  • Why Do Multi-Agent LLM Systems Fail? — a failure taxonomy worth extending
  • A Survey on Evaluation of LLM-based Agents
  • Holistic Agent Leaderboard — cost-aware evaluation

2. Fine-tuning small models for agentic tasks

Can a 4–9B open-weight model be made meaningfully better at tool calling, reflection, or planning with a modest fine-tune? This is squarely semester-sized: generate or collect traces, LoRA-tune, compare against prompting the same base model. (Pretraining is out of scope — see above.)

  • FireAct — fine-tuning on agent trajectories
  • AgentTuning — instruction-tuning for agent abilities
  • ToolLLM — training for large-scale API use
  • xLAM — a family of function-calling models
  • DeepSeek-R1 — see the distillation section: small models learning from reasoning traces

3. Agentic AI safety and security

Agent safety is not chatbot safety: the question is not “did the model say something harmful” but “what did the system actually do.” A strong architectural question from the idea doc: at which layer should prompt-injection defenses operate — model prompting, tool authorization, or execution monitoring?

  • Not What You’ve Signed Up For — indirect prompt injection, the founding paper
  • AgentDojo — an injection benchmark you can run
  • AgentHarm — measuring harmful task completion
  • Defeating Prompt Injections by Design (CaMeL)
  • Design Patterns for Securing LLM Agents

4. Tool use and MCP

Tool use looks solved in demos and is not solved scientifically. Selection is fragile to description wording, tool-set size, and near-duplicate distractors — and MCP adds questions about poisoning, permissions, and provenance.

  • Tool Preferences in Agentic LLMs are Unreliable — small description changes shift tool usage by more than 10×; a perfect paper to extend
  • What Are Tools Anyway? — the survey that maps the area
  • Gorilla — LLMs and massive API sets
  • Model Context Protocol: Landscape and Security

A clean experiment: give an agent 5, 20, 50, and 100 tools with progressively similar distractors, and measure selection accuracy, cost, and failure modes.

5. Memory and context

Older memory benchmarks test whether an agent can retrieve a fact; the open question is whether it uses remembered information appropriately when acting — and what it should forget.

  • Mem2ActBench - benchmark for evaluating long-term memory; can be easily extended
  • MemGPT — memory hierarchies
  • Generative Agents — memory in believable simulation
  • Mem0 and A-Mem — production memory systems

A clean experiment from the idea doc: compare append-everything, overwrite, recency-weighted, and conflict-aware memory policies as user preferences change; measure task success, stale-memory errors, and token cost.
