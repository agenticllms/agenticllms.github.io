Week 2b — Course Environment Setup

Setting up the project to pull the lecture files

Please follow these instructions carefully.

By the end you will have one folder that looks like this:

agentic-ai-course/
├── .venv/            your Python environment (created in step 3)
├── .env              your API keys (step 5)
├── lecture-files/    files from class, one folder per day (step 4, read-only)
│   └── W02b/
└── W02b/             your working copy of the day's files

1. Install uv

uv is a fast Python environment manager. It also installs Python itself, so you do not need to install Python separately — whatever Python you do or do not have on your machine, the result is the same.

  • macOS
  • Windows
  • Linux

In Terminal:

curl -LsSf https://astral.sh/uv/install.sh | sh

Then close and reopen the terminal, and verify:

uv --version

In PowerShell:

powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

Then close and reopen PowerShell, and verify:

uv --version
curl -LsSf https://astral.sh/uv/install.sh | sh

Then close and reopen the terminal, and verify:

uv --version

2. Create your course project

Make one folder for the whole course and open it in VS Code:

mkdir agentic-ai-course
cd agentic-ai-course
code .

If code is not recognized, open VS Code manually, then File, Open Folder.

From here on, run commands in VS Code’s integrated terminal (Terminal > New Terminal) so you are always in the right place.

3. Create the environment

From inside agentic-ai-course:

uv venv --python 3.13

This creates .venv, a self-contained Python 3.13 environment that lives in your project folder. Everything we install goes in here and nowhere else.

4. Get the lecture files and install the dependencies

git clone https://github.com/agenticllms/lecture-files.git
uv pip install -r lecture-files/requirements.txt
cp -r lecture-files/W02b W02b

The first command brings in the class files; the second installs every library the course uses into your .venv. Note there is no pip on its own anywhere in this course: it is always uv pip, which cannot install into the wrong Python. The third makes your working copy of today’s files.

Each class day, the process will involve the following: pull, then copy the day’s folder out and work in the copy.

cd lecture-files
git pull
cd ..
cp -r lecture-files/W03a W03a

(Windows PowerShell: Copy-Item -Recurse lecture-files/W03a W03a.)

Pulling is additive: it brings the new day’s folder and leaves previous days untouched. But here is the rule that keeps it that way: treat lecture-files as read-only and do your work in the copies. Running a notebook saves outputs into the file, which counts as a local edit, and local edits are what make a future git pull refuse. If lecture-files ever does get messy, reset it with git restore . from inside that folder — safe, because nothing of yours lives there.

5. Add your API keys

Copy the template to your project root and rename it:

cp lecture-files/example.env .env

Open .env in VS Code and paste in your keys — GOOGLE_API_KEY and TAVILY_API_KEY will be required later; the others are optional. Never commit or share this file, and never paste a key into a notebook cell.

6. Point VS Code at your environment

This is a crucial step:

  1. Open any notebook from your W02b/ copy.
  2. Click the kernel picker in the top-right corner of the notebook.
  3. Choose the interpreter at agentic-ai-course/.venv (it may be listed as .venv (Python 3.13)).

VS Code remembers this per notebook. If a notebook ever complains that a module is missing, check the kernel picker before anything else — nine times out of ten the notebook is quietly running some other Python.

7. Verify

Open W02b/W02b.1_LLM_API_Basics.ipynb and run the first cell. If it prints that the API key is loaded, you are done. If not, see below.

Some Common Errors

Symptom Cause Fix
ModuleNotFoundError Notebook is on the wrong kernel Kernel picker → choose .venv → restart kernel
pip: command not found Bare pip is not on your PATH Use uv pip install ... instead
No API key found .env missing, misplaced, or kernel started before you created it .env goes in the project root, next to .venv; then restart the kernel
Works in one notebook, not another The two notebooks are on different kernels Set both to .venv
uv: command not found right after install Terminal opened before the install finished Close and reopen the terminal
git pull refuses: local changes would be overwritten You ran or edited notebooks inside lecture-files cd lecture-files, then git restore ., then pull again. Work in copies from now on

Last, please keep in mind that environment problems are not a test of your ability; everyone hits them, including me.
